# Fast Maya demo

Maya's initial demo loads `/demos/maya-learning-v2.json`, a prepared synthetic LearningBundle generated by the actual `computeLearning` pipeline. The initial six-month replay is computed once offline, not on each new visitor's device. The bundle includes frozen per-symptom snapshots, source observations and journal entries. Labels were not manually substituted.

The demo clock is fixed to November 14–15 2026 and remains explicitly fictional. Do not relabel its history as real readings or silently shift its frozen issuance timestamps. Older fictional demo bundles are archived locally before loading this revised scenario. Current-version saved fictional edits remain preferred. New demo check-ins and advancing the demo still use the worker-based personal learner. Personal profiles never load this snapshot.

To regenerate from repository root:

```sh
npx esbuild research/prepare_fast_maya_demo.ts --bundle --platform=node --format=esm --outfile=work/prepare-maya.mjs
node work/prepare-maya.mjs
```

Commit the regenerated JSON with any model change. The versioned URL may be bumped when publishing a changed fixture. The browser validates the state, input and synthetic persona markers before persisting it. A missing or invalid asset produces an actionable error rather than silently starting the slow replay again.

Sites packaging now includes public demo assets and direct section HTML routes, including `/settings` for sign-in redirects. This preparation does not publish the site by itself.

The current prepared scenario starts before bleeding and has model-computed high fatigue/bloating estimates with low pelvic-pain/bowel estimates. This is not a hand-edited risk display and does not establish reliable advance pain warnings. The overview states only the returned per-symptom bands; selected wearable inputs are named without causal explanations.
